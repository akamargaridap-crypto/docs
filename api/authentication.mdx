Every request to the Kira API must include a valid API key as a Bearer token in the `Authorization` header. Kira uses API keys to identify your account, enforce rate limits, and control access to resources. Without a valid key, every request returns a `401 Unauthorized` response.

## Getting Your API Key

Generate a new API key from the AkaPeople dashboard. Each key is unique to your account and can be scoped per environment.

<Steps>
  <Step title="Log in to the dashboard">
    Go to [dashboard.akapeople.ai](https://dashboard.akapeople.ai) and sign in with your AkaPeople account credentials.
  </Step>
  <Step title="Open Settings">
    Click your profile avatar in the top-right corner, then select **Settings** from the dropdown menu.
  </Step>
  <Step title="Navigate to API Keys">
    In the left sidebar, click **API Keys** under the **Developer** section.
  </Step>
  <Step title="Create a new key">
    Click **New API Key**, enter a descriptive name (for example, `production-server` or `dev-local`), and click **Create**.
  </Step>
  <Step title="Copy your key">
    Your new API key is displayed once. Copy it immediately and store it somewhere secure.
  </Step>
</Steps>

<Warning>
  Kira displays your API key **only once** at creation time. If you lose it, you must revoke it and generate a new one. Store your key immediately in a secret manager (such as AWS Secrets Manager, HashiCorp Vault, or 1Password) or in an environment variable — never in source code.
</Warning>

## Using Your API Key

Include your API key in every request using the `Authorization` header with the `Bearer` scheme:

```
Authorization: Bearer YOUR_API_KEY
```

Here is a complete example of an authenticated request that sends a message to an existing session:

```bash
curl --request POST \
  --url https://api.akapeople.ai/v1/messages \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "session_id": "sess_abc123",
    "content": "What tasks do I have due today?"
  }'
```

Replace `YOUR_API_KEY` with your actual key. If the key is missing or malformed, the API returns:

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Missing or invalid API key.",
    "details": null
  }
}
```

## Code Examples

The following examples show how to authenticate a request in common languages and tools.

<CodeGroup>

```bash curl
curl --request POST \
  --url https://api.akapeople.ai/v1/messages \
  --header "Authorization: Bearer $KIRA_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "session_id": "sess_abc123",
    "content": "Summarize my pending tasks."
  }'
```

```python Python
import os
import requests

api_key = os.environ["KIRA_API_KEY"]

response = requests.post(
    "https://api.akapeople.ai/v1/messages",
    headers={
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json",
    },
    json={
        "session_id": "sess_abc123",
        "content": "Summarize my pending tasks.",
    },
)

data = response.json()
print(data)
```

```javascript Node.js
const response = await fetch("https://api.akapeople.ai/v1/messages", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${process.env.KIRA_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    session_id: "sess_abc123",
    content: "Summarize my pending tasks.",
  }),
});

const data = await response.json();
console.log(data);
```

</CodeGroup>

## Key Management

### Rotating Keys

Rotate your API keys periodically or immediately after a suspected leak. Follow these steps to rotate without downtime:

<Steps>
  <Step title="Create a new API key">
    Follow the steps in [Getting Your API Key](#getting-your-api-key) to generate a fresh key. Give it a name that distinguishes it from the old key.
  </Step>
  <Step title="Update your application">
    Replace the old key with the new one in your secret manager or environment variables. Deploy the update to your application.
  </Step>
  <Step title="Revoke the old key">
    Once your application is confirmed to be using the new key, revoke the old one (see below) to prevent any further use.
  </Step>
</Steps>

### Revoking Keys

To revoke a key, go to **Settings → API Keys** in the dashboard, find the key you want to remove, and click **Revoke**.

<Warning>
  Revoking a key is **immediate and irreversible**. Any application still using the revoked key will start receiving `401 Unauthorized` errors right away. Make sure your application is fully updated before you revoke an old key.
</Warning>

## Security Best Practices

<CardGroup cols={2}>
  <Card title="Use Environment Variables" icon="terminal">
    Store your API key in an environment variable and read it at runtime. Never hard-code it directly in your source files or configuration.
  </Card>
  <Card title="Never Expose Keys Client-Side" icon="eye-slash">
    Do not include your API key in front-end JavaScript, mobile apps, or any code that ships to end users. All API calls should go through your server.
  </Card>
  <Card title="Rotate Keys Periodically" icon="rotate">
    Establish a regular rotation schedule — for example, every 90 days — and rotate immediately if you suspect a key has been compromised.
  </Card>
  <Card title="Use Separate Keys per Environment" icon="layer-group">
    Create distinct API keys for development, staging, and production. This limits the blast radius if a key leaks and makes it easy to revoke access for a single environment.
  </Card>
</CardGroup>

<Tip>
  Name your environment variable `KIRA_API_KEY` across all environments to keep your codebase consistent. All code examples in this documentation use `KIRA_API_KEY` by convention.
</Tip>
